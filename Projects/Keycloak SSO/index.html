IAM Lab: Using Keycloak and Azure for MFA and RBAC

One login for two apps over OIDC and SAML, federated with Microsoft Entra ID, with roles driven by groups and MFA required by role.

Author: William Lacy  ·  Date: October 2026  ·  Environment: Home lab (Ubuntu VM, Docker) + Microsoft Entra ID tenant

Summary

I built a working single sign-on environment where Keycloak is the identity provider for two applications: Grafana over OpenID Connect and Wiki.js over SAML 2.0. Keycloak is federated with Microsoft Entra ID, so cloud users sign in with their Microsoft account and Entra MFA. Access in Grafana is decided entirely by Keycloak group membership, and a one-time password is required only for users holding an admin role.

Every control was tested with named test users, and each result is backed by a screenshot below.

The browser is redirected to the public sso.lab.local URL, while Grafana's back-channel token and userinfo calls go straight to Keycloak over the Docker network.

Key Keycloak settings

  • Grafana client: confidential, standard flow only (direct access grants off), exact redirect URI, with a groups client scope (Group Membership mapper, full path off) added as Default.
  • Wiki.js client: SAML, Client ID equal to the Wiki.js issuer, Name ID format email (forced), documents and assertions signed with RSA_SHA256, client signature not required, and User Property mappers for email and firstName.
  • Entra identity provider: alias entra, configured from the tenant's v2.0 discovery endpoint, client secret sent as post, scopes openid profile email, Trust Email on.
  • Browser flow browser-admin-mfa: a copy of the built-in flow, bound as the realm's browser flow. The conditional OTP sub-flow evaluates Condition - user role first, then OTP Form, with "user configured" disabled.

Findings

Revoking at the IdP doesn't end app sessions. After Bob's Keycloak session was signed out, his existing Grafana session kept working, while any new SSO login required credentials again. In production this needs short app session lifetimes or OIDC back-channel logout so that revocation takes effect immediately.

Federated logins skip the realm browser flow. Entra users never hit the Keycloak OTP step; their MFA is enforced upstream by Entra. That is the intended design here, but it means MFA policy must be checked at every identity provider, not only in Keycloak.

Next Steps

  • Turn on OIDC back-channel logout for Grafana and shorten its session lifetime.
  • Map Entra security groups to Keycloak groups instead of hardcoding every federated user as Editor.
  • Forward Keycloak events to my Wazuh manager and alert on repeated LOGIN_ERROR and on admin role changes.
  • Manage realms, clients and flows as code with the Terraform Keycloak provider.
  • Add WebAuthn (passkeys) as a phishing-resistant second factor for admins.
